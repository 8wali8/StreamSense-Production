# Handoff: retiring access links

Written 2026-09-19 for a fresh session. Read `CLAUDE.md` first (the "Auth" bullet under "API Gateway internals" and the sign-in paragraph under "Frontend internals"), then `docs/planning/branches/console-01-view-as.md` for the last change to this code. `console-auth.md` in this directory is the original sign-in handoff; it describes the access-link design this session removes, so read it for history only. A sibling session is working on the new-deal form at the same time (`first-deal.md`); the two do not share files beyond one sentence each in `CLAUDE.md`.

## The problem

Sign in with Twitch covers both kinds of person the console has: a streamer (confined to their own channel) and the operator (the owner, `8wali8`). A sponsor gets a share link, read-only for one deal. The demo at `/demo` is the answer for "have a look without an account". Access links, a bearer token minted by hand and carried in `#token=<jwt>`, predate all three and now serve nobody: they are a third kind of scope (no `role`, reads every channel, and since #67 cannot steer the pipeline, but can still create deals and share links for any channel through analytics-service). The owner decided on 2026-09-19 to retire them rather than specify a read-only viewer role.

## What exists today

- **Gateway.** `auth/JwtAuthTokenValidator` accepts a token without a `role` claim (the comment at the role read says so). `auth/AuthScope` has `isOperator()` (role operator), `isConfined()` (a role that is not operator), and treats the role-less case as "reads any channel"; `config/GatewayAuthWebFilter` applies `requiresOperator`, then the self-service rule from #68 (a role-less token is refused on `/api/chat/twitch/channels/*` and `/api/video/capture/channels/*` writes), then confinement. `config/GatewayWebSocketAuthInterceptor` puts the role on the session only when present. Tests: `auth/AuthScopeTest`, `graphql/AccessLinkScopeIntegrationTest` (three tests about role-less tokens), `graphql/ChannelScopeIntegrationTest`, `graphql/GatewayAuthWebFilterIntegrationTest` (uses `TestJwtTokens.validToken("demo-user")`, a role-less token, to prove a valid token passes), `web/TwitchSignInIntegrationTest`. `support/TestJwtTokens` has `validToken` (no role) and `tokenWithRole`.
- **Minting.** `tools/mint-jwt.py` (standard library; `--role` optional). `tools/deploy/deploy.sh` on the VM: `mint_token` wraps it with `--subject demo-viewer`; `verify_edge` mints a ten-minute token to prove the gateway answers with one; `cmd_link` and `access_link` print a 30-day link; `print_sharing_instructions` runs at the end of every deploy; `cmd_token` mints a bare token. Keep it shellcheck-clean (`-S style`, run in the `koalaman/shellcheck:stable` container).
- **Console.** `features/access/LoginPage.tsx`: the Twitch button when `GET /auth/providers` offers it, an "or" rule, "Paste your access link or token below", the field, "Open the console", and the demo line. `features/access/AccessGate.tsx` renders it until local storage holds a usable token. `src/lib/auth-token.ts`: `captureAccessLink` (the fragment capture, which is also how the Twitch callback delivers the token; keep it), `authTokenFromInput` (the pasted-link parser; goes), `authTokenClaims` (`role` null for a link), `isOperatorSession` and `canStartMeasurement` (both treat a role-less token as a viewer), `AccessPanel.tsx` ("Access link" / "Until <date>" state, and `claims.role ?? "viewer"`). Tests: `auth-token.test.ts` (`TOKEN` is a role-less fixture used widely), `AccessGate.test.tsx`, `AccessPanel.test.tsx`, `view-as.test.ts`, `src/test/tokens.ts` (`fakeJwt`).
- **Docs.** `docs/hosting.md` (the sharing section, "Send a viewer the access link…", the `link`/`token` subcommands, the Twitch section's last sentence), `docs/howtorun.md` (two `mint-jwt.py` examples for verifying auth locally), `CLAUDE.md` (the auth bullet's sentence about a token without a role, and the frontend sign-in paragraph), `docker-compose.prod.yml`'s header comment ("viewers use a token from tools/mint-jwt.py"), `docs/planning/cloud-hosting.md` (a decision record; leave it).
- **Not affected.** Share links (`X-StreamSense-Share`, `src/lib/share-token.ts`) are a separate path and stay. The Compose smoke test and CI run with auth off. The demo sends no token.
- **Live state.** The VM runs `main` at `eff6d05`. The last access link was printed by the 2026-09-19 deploy and was never forwarded to anyone; nothing in use breaks when links stop working.

## What is unknown

- Whether anything in `k8s/` or the kind guide (`docs/kubernetes-kind.md`) tells a reader to mint a role-less token; grep for `mint-jwt` and `token` before deciding the docs are done.
- Whether `verify_edge` should mint `--role operator` (simplest; the health query is a read either way) or `--role streamer --login verify`; operator is fine, the token lives ten minutes and never leaves the VM.

## Approach, in order

1. Branch `auth/06-retire-access-links` from `origin/main` in a worktree.
2. Gateway: `JwtAuthTokenValidator` refuses a token whose `role` is missing or not `operator`/`streamer` with a new reason (`missing_role`), so the 401 says why. `AuthScope` becomes two cases: `isOperator()` and everything else confined; delete `isConfined()` if nothing needs the name, and the self-service rule's "role-less" branch in `GatewayAuthWebFilter`. `GatewayWebSocketAuthInterceptor` always has a role. Tests: `AccessLinkScopeIntegrationTest` becomes a test that a role-less token is refused with `missing_role`; `AuthScopeTest` loses its access-link case; every `validToken(...)` used to pass the gate switches to `tokenWithRole(...)`. `mvn -pl api-gateway verify` in the `maven:3.9-eclipse-temurin-21` container (`~/.m2` mounted, `-Dmaven.gitcommitid.skip=true`, `spotless:apply` first, JaCoCo floor in the POM must hold). Run the container detached with `docker run -d --name … sh -c "mvn … > /work/.testlogs/<log> 2>&1"` and `docker wait` it: a background shell on this machine gets killed under memory pressure and orphans the container.
3. `mint-jwt.py`: `--role` required, help text and module docstring updated. `deploy.sh`: `verify_edge` mints `--role operator`; `cmd_link`, `access_link`, and `print_sharing_instructions` removed, along with the `link` case in the dispatch; `cmd_token` mints `--role operator` and says so; the deploy's final lines print the console URL and nothing else. Shellcheck.
4. Console: `LoginPage` is the Twitch button and the demo line (keep the header, the teal accent, and the failure sentence from `?signin=<reason>`; when `/auth/providers` says Twitch is off, say that sign-in is not set up on this deployment rather than offering a field). `authTokenFromInput` and its tests go; `AccessGate` no longer accepts a pasted token; `AccessPanel` drops the "Until <date>" state; `isOperatorSession` and `canStartMeasurement` keep their "no token at all" case (auth off locally) and lose the role-less case; `auth-token.test.ts` fixtures get a role. Frontend gate (`codegen:check`, `lint`, `format:check`, `test:coverage`, `build`); the coverage floors in `vite.config.ts` must hold.
5. Docs as listed above; `CLAUDE.md` says a token always carries a role and that the sign-in page is the Twitch button. Branch note at `docs/planning/branches/auth-06-retire-access-links.md`. PR, merge on the owner's word, CI on `main`, deploy, then from the VM: a token minted without `--role` (use `python3 tools/mint-jwt.py` directly with the secret from `secrets/`) gets 401 `missing_role` on a GraphQL health query, and `sudo streamsense-deploy verify` still passes.

## Conventions and workflow to keep

- One branch, one PR, merged with a merge commit (`gh pr merge --merge`) after the owner says so; deploy only after CI on `main` is green: `gcloud compute ssh streamsense-demo --zone us-central1-a --command "sudo streamsense-deploy"`. `gh` and `gcloud` run from WSL (`wsl.exe -e bash -lc '...'`, `~/.local/bin/gh`, from the main checkout under `/mnt/c/...`), not from Git Bash. Maven and shellcheck run in Docker as above.
- Commits carry the owner's identity (`GIT_AUTHOR_NAME="Ujjawal Prasad"`, `GIT_AUTHOR_EMAIL="ujjawalprasad111@gmail.com"`, committer likewise) and the attribution trailers the session's system reminder gives.
- Never print a token in chat; redact `#token=` and bearer values from any command output, including the deploy script's.
- The Twitch consent screen is the owner's click, never the session's; a repeat sign-in usually completes without one.
- The owner reads short, plain messages: what changed, what was verified, what to check by hand.
