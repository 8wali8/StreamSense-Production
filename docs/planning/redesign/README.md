# Redesign branches

The user-stories redesign described in `product-direction.md`. `redesign/main` is the integration branch for this line: it was cut from `main` and carries the plan. Each piece of work is a sub-branch `redesign/NN-slug` cut from `redesign/main`, in a worktree under `StreamSense-worktrees/redesign-NN-slug`, and merges back into `redesign/main` after review, following the hardening-branch workflow (each sub-branch ships `docs/planning/redesign/NN-slug.md` with verification results and manual checks for the reviewer). `main` receives `redesign/main` once, when the line is complete enough to ship.

The cloud move runs on its own line and merges to `main` independently. When it lands, `main` is merged into `redesign/main` once and any conflict is resolved there, never on a sub-branch. The files both lines are expected to touch are the network policy list and the secrets examples.

Sub-branches that do not depend on each other run in parallel. Dependencies: 03 needs 02; 04 needs 03; 05 needs 02 and 04; 06 needs 05; 07 needs 06 and the cloud line's public domain. 01 and 02 depend on nothing but the plan.

Every change on this line must name the story (S1 to S7) it serves or the ops page it clears. Anything else is out of scope.

## Design work

Mockups are made before 04 and 05, not before 01 and 02, which need no design decisions. One canvas, four artboards: streamer home, deal page, session report (most detail), ops. Reviewed against the seven stories; anything on an artboard that answers no story is removed before code.

## Conventions carried over

- Frontend: routes are feature folders under `src/features/`; generated GraphQL types only; `useLiveFeed` for history plus subscription; every visible error through `describeError`; MSW at the network edge in tests; no component nobody renders.
- Java: new tables through Flyway; new event fields in the JSON schema in the same commit; REST errors as problem details; no HTTP client without a timeout; new outbound dependency means a network policy rule in the same change.
- Every branch note lists what was verified, how, and what the reviewer should check by hand.
